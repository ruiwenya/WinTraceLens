# WinTraceLens V2 Preview

WinTraceLens V2 是面向 Windows 应急响应的增强预览版。它继续保留进程、主机信息、事件日志、历史通信、文件痕迹、YARA 和 AI 辅助分析，并把 Rootkit/异常驱动排查从单一列表升级为多源交叉核查。

## 本阶段新增

- 内核驱动多源核查：交叉比较 PID 4 内核模块枚举、`HKLM\SYSTEM\CurrentControlSet\Services` 驱动服务项、`C:\Windows\System32\drivers` 磁盘文件、Amcache `InventoryDriverBinary` 历史清单，以及 7045、4697、Sysmon 6 驱动安装或加载事件。
- V2 核查摘要：分别展示“内核有、注册表无”“内核有、磁盘无”“注册表有、磁盘无”“注册表有、当前未加载”“磁盘孤立文件”“内核与 Amcache 差异”“Amcache 与当前磁盘差异”和事件证据。
- 风险分级降噪：停用或按需启动的驱动仅作为基线差异；已加载驱动文件缺失、驱动服务指向文件缺失等情况优先进入高关注。
- 驱动风险快捷筛选：支持仅看高风险、多源不一致、文件缺失、签名异常和有事件证据的项目。
- 驱动表列排序：级别、评分、驱动名、类型、签名、MD5、基址、大小、路径、服务项、启动类型、事件关联、Amcache 字段、多源差异和原因均可单击表头排序。
- 核查摘要导出：除风险明细 CSV 外，可单独导出 V2 多源核查摘要 CSV。
- 案件调查工作台：按调查日期聚合进程启动、当前连接、事件日志、历史通信和文件/执行痕迹，并按 SMB、挖矿、远控、蠕虫、账户入侵、PowerShell、Rootkit 等场景重新评分。切换场景复用缓存证据，不会重复跑全量采集。
- 场景重点与证据组跳转：默认按场景分数展示需优先核查的实体；进程、主机、文件、通信、日志、驱动等覆盖统计可直接点击进入对应证据组。
- 全局实体搜索：可用 PID、MD5、IP、域名、用户名、进程、服务、计划任务或路径同时搜索多个证据源；所有主要列表支持 `/pattern/i` 或 `re:pattern` 正则筛选。
- 证据收藏：时间线和实体搜索结果可在本次程序运行内收藏，页面来回切换不会丢失。
- 传统执行痕迹：在已有 Prefetch 和 Recent 快捷方式基础上，增加原生 USN Journal 读取、MFT 证据定位、Amcache、Shimcache 路径提取、SRUM 数据库定位、PCA、UserAssist、JumpList 容器和 PowerShell PSReadLine 历史采集。
- Amcache 原生解析：直接读取本机或离线 `Amcache.hve`，按实际键结构识别新旧 schema，结构化展示 SHA1、Publisher、产品、BinaryType、ProgramId 关联、PE 链接时间和记录时间；PowerShell 读取仅作为兼容兜底。
- Amcache 锁定文件读取：先尝试普通读取和完整共享标志；仅在本机实时 Hive 出现共享冲突时，依次尝试注册表一致性快照和管理员权限下的临时 VSS 卷影副本。VSS 用完立即删除，并在受保护的注册表状态项中记录未完成清理，下一次采集会清理异常退出留下的 WinTraceLens 快照。
- Amcache 应用关联：对未关联到 `InventoryApplication`/`Programs` 且位于 AppData、ProgramData、Temp 或用户目录的文件提高关注权重，并按当前文件 Authenticode 状态进一步核查。
- Amcache 驱动清单：把 `InventoryDriverBinary` 作为驱动多源核查的历史证据，突出随机名、用户可写路径、未签名元数据和当前磁盘缺失的组合，不把单一历史残留直接判成高风险。
- 文件痕迹列排序：普通文件痕迹表和 Amcache 专用表的全部可见字段均支持单击表头切换升序、降序，空值固定排在末尾。
- 案件采集缓存：完整采集结果在本次程序运行内复用，只有主动点击“采集案件证据”才重新读取高负载证据源。
- PowerShell 降噪：WinTraceLens 采集脚本统一写入内部标记，并按脚本块、运行空间、进程和时间窗口排除自身日志；案件时间线、AI 证据、进程关联日志和“全部事件”导出默认隐藏普通引擎生命周期与 Provider 日志，PowerShell 专页仍保留非工具原始事件。

## 使用建议

1. 右键以管理员身份运行 `WinTraceLens.exe`。
2. 打开“威胁分析”，切换到“内核驱动风险”。
3. 先看 V2 多源核查摘要，再优先核查“内核枚举与驱动目录对比”“Services 与磁盘文件对比”和“Amcache 高关注历史驱动”。
4. 对高关注项结合签名、MD5、Amcache SHA1、服务 ImagePath、注册表路径、加载事件和网络攻击时间线复核。
5. 使用“导出核查摘要”和“导出 CSV”保留现场证据，避免只依赖截图。
6. 打开“案件调查”，选择调查场景和日期范围；先看“场景重点”，点击覆盖统计进入具体证据组，再围绕 PID、哈希、IP、用户或路径进行横向关联。

## 检测边界

V2 当前仍是用户态取证工具。多源差异能够发现文件删除、残留服务、异常加载路径、随机驱动名和部分视图不一致，但不能证明不存在 DKOM 隐藏驱动或隐藏进程。

- `Toolhelp32Snapshot` 与 `NtQuerySystemInformation(SystemProcessInformation)` 不是足以对抗 DKOM 的真正独立进程来源。
- `Win32_Process` 的多个字段仍映射到 `SYSTEM_PROCESS_INFORMATION`，因此本阶段不把 WMI 查询包装成“独立 Rootkit 检测源”。
- “Services 有但内核未加载”常见于停用、按需启动、启动失败或卸载残留，不能单独判定恶意。
- “驱动目录孤立文件”可能来自驱动仓库、系统更新或卸载残留，需要叠加签名、时间和名称特征判断。
- Amcache 证明系统曾记录过文件或驱动元数据，不单独证明文件执行或驱动加载。新 schema 的键最后写入时间主要反映兼容性评估器记录/更新时间；旧 schema 时间也必须与 Prefetch、事件日志、USN 等证据交叉验证。
- Amcache `FileId`/`DriverId` 中的 SHA1 是历史缓存标识，不是本次采集对当前完整文件重新计算的哈希；威胁情报查询未命中不能据此判定安全，应再计算当前文件哈希。
- `Amcache.hve` 可被具有高权限的进程离线修改，因此异常稀少或“过于干净”的 Hive 也不能作为排除恶意活动的依据。
- 当实时 `Amcache.hve` 被独占锁定时，VSS 回退会短暂改变系统卷影副本状态，因此只在管理员模式和共享冲突条件下执行；文件痕迹页面会明确显示该操作，正常路径会在解析后立即删除临时快照。
- USN Journal 使用 Windows 原生只读接口采集，但当前只保留文件引用号和文件名，尚未将 Parent FRN 递归还原成完整路径；`$MFT` 仅提供证据位置，未在在线主机上直接解析或复制。
- Shimcache 当前按系统注册表二进制做路径级启发式提取，不解析所有版本的时间与标志位，且条目不能单独证明执行。
- JumpList 当前采集容器文件及其时间戳，尚未解析容器内全部目标；SRUM 当前定位 ESE 数据库及元数据，尚未解析应用流量明细。
- PowerShell PSReadLine 历史只保存命令顺序和历史文件更新时间，不能把单条命令精确绑定到执行时间。
- Prefetch 当前使用文件名和最后写入时间作为近似活动线索，尚未解析全部运行次数与多次运行时间；不能把近似时间直接当成确定执行时间。
- 对抗内核对象摘链仍需可信的签名只读内核采集器、离线内存镜像和交叉视图分析。

## 后续 V2 路线

- 设计最小权限、只读、可审计的内核采集协议；正式发行前必须解决 EV/微软签名、驱动安全审计、兼容性和崩溃风险。
- 增加离线内存镜像导入和外部取证工具结果关联，不在感染主机上直接做高风险写入操作。
- 增加驱动服务注册表最后写入时间、驱动文件时间线和网络攻击时间线的统一关联视图。
- 为每次采集生成可校验的证据清单和哈希，提升取证包的完整性说明。

```powershell
go build ./...
go build -trimpath -ldflags "-H windowsgui -s -w" -o dist\WinTraceLens.exe .\cmd\wintracelensgui
go build -trimpath -ldflags "-s -w" -o dist\WinTraceLens-cli.exe .\cmd\wintracelens
```
