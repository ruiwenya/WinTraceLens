# WinTraceLens

WinTraceLens 是一款面向 Windows 应急响应和主机安全排查的本地分析工具。它使用 Go 编写，通过 WebView2 提供桌面 GUI，把进程、持久化、事件日志、网络通信、文件执行痕迹、内存异常和内核驱动等证据集中到同一个调查界面中。

项目适合用于挖矿木马、蠕虫传播、远控木马、异常登录、SMB 横向攻击、PowerShell 攻击和可疑驱动等场景的初步排查。它的目标是帮助分析人员快速建立主机视图、缩小调查范围并导出线索，不替代 EDR、专业内存取证框架或完整的离线取证平台。

## 主要功能

### 进程信息

- 展示 PID、父进程、CPU、内存、线程、句柄、连接数、创建时间和可执行文件路径。
- 计算可访问文件的 MD5，并标记系统文件、已签名、无签名及签名异常状态。
- 对比 Toolhelp 与 NT 系统信息两个用户态进程视图，提示枚举差异，但不把它描述为 DKOM 检测能力。
- 支持按连接数排序、关键词或正则筛选、CSV 导出和打开文件所在位置。
- 进程详情提供模块列表、模块 MD5、签名状态和当前网络连接。
- 对 PID 4/System 使用专门的内核模块枚举，补充普通进程模块接口无法读取的驱动信息。
- 可围绕选中进程关联服务、计划任务、启动项、历史通信和事件日志线索。

### 主机信息

- 汇总 Windows 服务、计划任务、启动项、本地用户、IFEO 镜像劫持项和 WMI 永久事件订阅。
- 展示路径、命令、账户、状态、MD5 和签名信息，便于定位持久化入口。
- 通过原生 COM 枚举 `root\subscription` 中的过滤器、消费者和绑定关系，保留孤立对象，并对精确定时触发、8.3 短路径、用户可写路径、SID 不一致及脚本代理执行等组合信号评分。
- 提供服务管理器、任务计划程序、系统配置启动项、本地用户和组、注册表编辑器快捷入口，方便与系统原生界面交叉核对。
- 支持正则筛选和分表 CSV 导出。

### 风险线索

- “规则关注项”根据路径、签名、文件状态、服务和启动项等规则生成待核查条目。
- “行为关联”把进程、持久化项、实时网络、历史日志和内存异常放在同一条线索中重新评分。
- 对浏览器、办公软件、安全软件、WinTraceLens 自身及常见正常内存行为进行降噪。
- 风险等级只是排查优先级，不是恶意判定结果。

### 威胁分析

- 内存异常：检查私有可执行内存、RWX/写拷贝可执行区域和异常线程入口等用户态特征。
- 内核驱动风险：交叉比较 PID 4 内核模块、Services 驱动服务项、驱动目录文件、Amcache 驱动历史和驱动加载事件。
- 关联 7045、4697、Sysmon 6 等服务安装或驱动加载证据。
- 突出已加载但文件缺失、注册表与内核视图不一致、随机名称、用户可写路径及签名异常等组合风险。
- 提供高风险、多源不一致、文件缺失、签名异常和事件证据快捷筛选，并可导出核查摘要。

### 案件调查

- 按日期范围聚合进程、主机信息、当前连接、历史通信、事件日志、文件痕迹和驱动风险。
- 提供通用排查、445/SMB、挖矿、远控、蠕虫、账户入侵、PowerShell 和 Rootkit 等调查场景。
- 场景选择会对同一批缓存证据重新评分和排序，不会伪装成只采集某一种场景的专用取证器。
- “场景重点”优先展示与当前场景相关的实体，并可从证据覆盖统计跳转到对应证据组。
- 全局搜索支持 PID、MD5、IP、域名、用户名、进程、服务、任务和路径。
- 支持 `/pattern/i` 与 `re:pattern` 正则筛选、分页和本次运行内的证据收藏。

### 文件痕迹

- 扫描最近修改文件、最近运行线索和 Temp 目录可疑文件，可选择指定目录和时间范围。
- 原生读取 NTFS USN Journal，并提供 `$MFT` 证据位置；当前不会在线完整解析 `$MFT`。
- 原生解析本机或离线 Amcache Hive，展示 SHA1、Publisher、产品、BinaryType、ProgramId 关联、PE 链接时间和记录时间。
- Amcache 被占用时可在管理员模式下使用临时 VSS 快照读取，并在完成后清理快照。
- 补充 Prefetch、Recent LNK、JumpList、Shimcache、PCA、UserAssist、PowerShell PSReadLine 和 SRUM 证据。
- 在受控落地点内检查 `desktop.ini` 结构异常，包括零字节文件、异常体积、INI 结构破坏和 ShellClassInfo 后的长尾 UTF-16 空白编码；该检查不受“最近修改”时间窗口限制。
- 每个取证源都显示可用性和采集提示，避免把系统未启用、权限不足或记录不存在误认为程序故障。
- 所有主要列支持表头升降序排序，并提供取证源筛选、正则搜索和 CSV 导出。

需要注意：当前 Prefetch 主要使用文件名和最后写入时间作为活动近似值；JumpList 主要定位容器文件；SRUM 主要定位数据库及元数据；Shimcache 为路径级启发式提取。这些来源不能单独证明文件在某个精确时间执行。

### 历史通信

- 分开展示历史连接、DNS 记录、当前连接、短连接监测和全部通信证据。
- 程序运行期间每秒采样 Windows TCP 表，保留已经消失的连接、首次/最后发现时间、出现次数、采样次数和 SYN-SENT 状态。
- 尝试读取 Sysmon 网络事件、Windows Filtering Platform 5156/5157、Windows 防火墙日志和 DNS Client 日志。
- 补充 DNS 缓存、ARP、路由表和 netstat 快照。
- 支持 IP、域名、PID、进程和来源筛选，以及通配式搜索和正则搜索。

Windows 默认通常不会同时启用 Sysmon、WFP 连接审计和防火墙文本日志，因此“历史通信”可能只有部分证据。DNS 缓存通常也没有可靠的查询时间和进程归属，不能单独用于恶意进程归因。短连接监测仅保留本次程序运行期间的用户态采样结果，持续时间短于采样窗口的连接仍可能漏采，不能替代 WFP、ETW、Sysmon 或抓包。

### 事件日志

- 支持自定义开始和结束日期，避免一次读取全部事件造成长时间等待。
- 分为全部、登录/注销、RDP、服务创建、用户账户、PowerShell、SQL Server 和日志健康页面。
- 覆盖常见的登录成功、登录失败 4625、RDP 会话、服务安装、用户创建和 PowerShell 活动。
- 每个分类使用专用字段和提示信息，所有主要列均支持表头排序。
- 提供事件详情弹窗，可复制原始信息，并支持 CSV 导出。
- “日志健康”说明日志源是否存在、审计是否启用以及证据缺失的可能原因；未安装 SQL Server 时会明确提示。
- 对 WinTraceLens 自身产生的普通 PowerShell 引擎生命周期和 Provider 噪声进行过滤。

### YARA 扫描

- 调用本机外部 `yara.exe` 或 `yara64.exe`，程序本身不内置 YARA 引擎和第三方规则库。
- 支持选择规则目录、批量检测规则语法并跳过错误规则。
- 支持文件夹扫描和勾选进程后的内存扫描。
- 支持超时、并发限制、扫描进度和中途停止。
- 结果按文件或进程聚合，只突出命中规则、错误和超时，减少大量“未命中”回显。

### 一键导出取证包

- 各页面右上角的“导出取证包”支持全选或勾选部分证据来源，生成 ZIP；生成 ZIP 本身不重复扫描。
- 可点击“一键获取证据”，按勾选来源及必要关联依赖依次采集，无需逐页打开。日志默认最近 7 天，可调整日期、每源条数和进程上限；文件痕迹默认最近 7 天，沿用原有临时 VSS 读取与清理逻辑。
- 覆盖进程、进程模块、当前连接、主机信息、风险线索、注册表异常、事件日志、历史通信、文件痕迹、内存异常、驱动风险、案件调查和已完成的 YARA 结果。“Go 原生落地点”合并在“文件痕迹”中，不再单独勾选。YARA 需要指定规则，不由一键采集自动运行。
- 包内提供完整 JSON、分表 CSV、`summary.txt`、采集提示、`manifest.json` 和 SHA-256 文件清单 `hashes.csv`。CSV 保留后台完整字段，不受页面隐藏列、关键词或分页影响，并防止公式注入。
- 每种采集参数保留最近一次成功快照；不同日期范围或目录的结果分组保存。清单记录采集时间、参数、未勾选及未采集来源，缓存过期不影响导出。必要依赖可参与关联分析，但未勾选依赖的原始数据不单独加入 ZIP。
- 一键采集显示阶段百分比，可停止后续采集；正在执行的系统查询需完成或超时收尾，已完成数据会保留。普通接口等待及 ZIP 打包进度标注“估算”，不是剩余时间或成功率。
- 不包含本工具保存的 API Key、AI 对话、可执行样本、内存转储、原始注册表二进制值或原始 EVTX；刷新失败会保留错误提示与旧快照，不能把未采集或采集失败当作没有异常。需原始样本时使用相应的单项证据导出功能。
- 生成过程支持取消，原始包内容和压缩包均限制为 256 MB。取证包含主机敏感数据，应按内部证据保管要求保存。

### AI 辅助分析

- 支持 OpenAI、DeepSeek、Kimi、Qwen 和自定义 OpenAI 兼容接口。
- 可选择要发送的证据范围，并在发送前查看完整 Prompt 预览。
- 支持基础脱敏，替换内网 IP、用户目录、UNC 主机名和域账户标识。
- 支持连续追问，模型设置、API Key 状态和对话在本次程序运行期间保留，关闭程序后清空。
- API Key 仅保存在当前进程内存中，前端读取会返回“已保存”状态而不是明文 Key。

AI 分析会把用户确认的证据发送到所选在线模型服务。企业内网、客户主机或受合规约束的环境应先核对预览和脱敏结果，优先使用内部部署的兼容接口。

## 推荐调查流程

1. 右键选择“以管理员身份运行”启动 `WinTraceLens.exe`。
2. 从进程列表按连接数、CPU、内存、签名和路径筛查异常进程。
3. 查看可疑进程的模块、当前连接和关联证据。
4. 在“风险线索”和“威胁分析”中检查持久化、内存异常及驱动多源差异。
5. 根据事件发生时间进入“案件调查”，选择对应场景并缩小日期范围。
6. 使用全局搜索围绕 PID、哈希、IP、域名、用户和路径进行横向关联。
7. 导出关键列表和核查摘要，并在隔离环境中继续做样本、内存镜像和威胁情报分析。

## 下载与运行

最新 WebView2 预览版可从 [GitHub Releases](https://github.com/ruiwenya/WinTraceLens/releases) 下载：

- `WinTraceLens.exe`：桌面 GUI 版本，推荐普通用户使用。
- `WinTraceLens-cli.exe`：启动本地 HTTP 服务并使用默认浏览器打开界面，适合调试和浏览器模式。

GUI 版本需要 Microsoft Edge WebView2 Runtime。建议在 Windows 10、Windows 11 和较新的 Windows Server 上使用，并尽量以管理员权限运行，否则安全日志、PID 4 模块、部分进程路径、签名和系统取证源可能读取不完整。

CLI 示例：

```powershell
WinTraceLens-cli.exe
WinTraceLens-cli.exe -no-browser
# 仅在确实需要固定端口时指定：
WinTraceLens-cli.exe -addr 127.0.0.1:8787
```

GUI 和 CLI 默认监听 `127.0.0.1:0`，由 Windows 分配当前可用端口，不依赖固定的 `8787`。本地服务使用启动随机令牌、会话 Cookie、API 请求头和同源检查限制访问。不要将 `-addr` 改为对外网卡地址，除非已经在隔离环境中增加了额外访问控制。

如果旧机器仍提示 `8787` 无法启动，通常说明运行的是旧版 EXE、CLI 旧构建，或快捷方式附加了 `-addr 127.0.0.1:8787`。可用 `netstat -ano | findstr :8787` 核对占用，但最新默认构建不需要该端口。

### 老系统版本

Windows 7、Windows Server 2008 R2 和 Windows Server 2012/2012 R2 请使用独立的 [WinTraceLens-Legacy](https://github.com/ruiwenya/WinTraceLens-Legacy) 项目。Legacy 使用 Go 1.20.x 和 Windows 原生 GUI，不依赖 WebView2，但功能实现和证据深度与本项目不完全相同。

## 从源码构建

当前发布构建已使用 Go 1.26.3 验证。

```powershell
go build ./...
go build -trimpath -ldflags "-H windowsgui -s -w" -o dist\WinTraceLens.exe .\cmd\wintracelensgui
go build -trimpath -ldflags "-s -w" -o dist\WinTraceLens-cli.exe .\cmd\wintracelens
```

也可使用统一构建脚本：

```powershell
.\scripts\build-release.ps1 -Version 2.0.0-preview
```

### 发布签名与 Smart App Control

公开发布的 `WinTraceLens.exe` 和 `WinTraceLens-cli.exe` 应使用同一个受信任发布者的 Authenticode 代码签名证书签名，并添加 SHA-256 RFC 3161 时间戳。自签名证书不能解决普通 Windows 11 终端上的 Smart App Control 信任问题。

使用证书存储中的发布证书构建并签名：

```powershell
.\scripts\build-release.ps1 `
  -Version 2.0.0-preview `
  -SignToolPath "C:\Program Files (x86)\Windows Kits\10\bin\<SDK版本>\x64\signtool.exe" `
  -CertificateThumbprint "<代码签名证书指纹>"
```

签名必须是构建流程的最后一步；签名后不要再压缩修改 EXE、写入资源或补丁。每次 Release 同时发布脚本生成的 `SHA256SUMS.txt`。若 Microsoft Defender 将文件明确判定为恶意软件或 PUA，而不是仅由 Smart App Control 阻止未知应用，应向 Microsoft 提交该版本进行误报复核，不应要求用户长期关闭 Defender。
可选测试：

```powershell
go test ./...
```

部分安全软件可能对未签名的应急响应工具、进程枚举、内存读取或测试 EXE 产生告警。建议核对源码和哈希后，在授权的隔离测试环境中验证，不建议通过长期关闭安全软件来规避告警。

## 检测边界

- WinTraceLens 当前是用户态工具，不能证明不存在 DKOM 隐藏进程、隐藏驱动或内核级 Hook。
- Toolhelp、NT 系统信息和 WMI 并不是足以对抗高级 Rootkit 的完全独立数据源。
- 内存异常规则只能提供可疑内存区域和线程入口线索，不能替代完整内存镜像及 Volatility 等离线分析。
- “文件缺失”“未签名”“枚举不一致”和“历史记录存在”都需要结合时间线、签名、哈希、路径和业务环境复核。
- Amcache、Shimcache、Prefetch、UserAssist、LNK 和 JumpList 的时间语义不同，不能统一解释为精确执行时间。
- 日志证据完整度取决于系统版本、审计策略、日志保留时间、权限以及相关日志源是否启用。
- 工具输出是调查线索和优先级建议，不是自动化恶意定性结论。

## 安全与授权

本项目仅用于已授权的安全排查、应急响应、内部测试和研究。请勿在未授权系统上运行、扫描进程内存或收集主机数据。
